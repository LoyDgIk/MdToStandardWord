# md2std —— Markdown 转团体标准（GB/T 1.1—2020）标准文本 Word

把用 Markdown 写的标准草稿，一键转换成符合 GB/T 1.1—2020 排版的**团体标准**标准文本 Word。
章/条编号、页眉页脚、封面、前言、目次等全部由模板自动处理，你只需专注内容。

## 安装

```
pip install -r requirements.txt
```

依赖：`python-docx`、`markdown-it-py`、`PyYAML`。

## 使用

```
python -m md2std examples/地热温泉资源开发利用规范.md -o out.docx
```

`examples/地热温泉资源开发利用规范.md` 是一份**完整的真实标准范例**（由 MinerU 导出的
PDF→Markdown 经本约定改写而成），覆盖封面、前言、引言、10 个正文章、术语、无标题条、
破折号列项、表格、规范性/资料性附录、参考文献，可作为书写模板对照。

可选参数：

- `-o, --output`  输出 .docx 路径（默认与输入同名）
- `-t, --template`  指定模板（默认使用内置团体标准模板）

转换后用 Word 打开，**首次打开时在“是否更新域”提示中选“是”**即可生成目次页码。

## Markdown 写作约定

### 1. 文件头（YAML front matter，放在文件最顶部）

```yaml
---
standard_type: 团体标准
number: T/CCF 001—2024          # 标准编号
replaces: T/CCF 001—2020        # 可选：被代替标准号
title: 智能座舱分级与综合评价      # 标准中文名称
title_en: Classification ...     # 英文译名
ics: "43.040.99"                # ICS 号（务必加引号，否则 27.010 会被当成数字丢掉末尾 0）
ccs: T 09                       # CCS 号
publish_date: 2024-03-15        # 发布日期
implement_date: 2024-04-01      # 实施日期
publisher: 中国计算机学会         # 发布单位
foreword:
  patent_note: true             # 是否加专利提示句（默认 true）
  proposer: 中国计算机学会         # 提出单位
  owner: 中国计算机学会           # 归口单位（与 proposer 相同会合并为“提出并归口”）
  draft_orgs: [单位甲, 单位乙]    # 起草单位
  drafters: [张三, 李四]          # 主要起草人
  replace_changes:              # 可选：主要技术变化（破折号列项）
    - 更改了……
    - 增加了……
  extra_notes:                  # 可选：前言末尾附加句，如首次发布说明
    - 本文件为首次发布。
introduction: |                 # 可选：引言（无则不生成引言节）
  第一段……
  第二段……
---
```

> 提示：ICS 号、含前导零的编号等建议加引号写成字符串，避免被 YAML 当作数字解析。

### 2. 正文（标题不要手写编号，模板会自动编号）

| Markdown | 输出样式 | 自动编号 |
| --- | --- | --- |
| `# 范围` | 章标题 | 1、2、3… |
| `## 一般要求`（有标题条） | 一级条标题 | 5.1 |
| `### 子要求`（有标题条） | 二级条标题 | 5.1.1 |
| `#### …` | 三级条标题 | 5.1.1.1 |
| `4.2.1  正文……`（无标题条） | 二级无标题等 | 自动 4.2.1（编号自动续接） |
| 普通段落 | 标准文件_段 | — |
| `- 项` | 破折号列项 | 破折号对齐段首2字 |
| `1. 项` | 字母编号列项 | a) b) c) |
| 嵌套有序项 | 数字编号列项 | 1) 2) |
| `注：…` / `注1：…` | 注 / 注× | — |
| `示例：…` / `示例1：…` | 示例 | — |

**有标题条 vs 无标题条**：
- **有标题条**（编号后跟简短标题，下面才是正文）→ 写成 ATX 标题，*不写编号*，由模板自动编号。
  例：`## 开发利用原则` → “4.1　开发利用原则”。
- **无标题条**（编号后直接是整段正文，没有单独标题）→ 写成普通段落，开头保留编号
  形如 `4.2.1  开发地热温泉资源前，应……`。**编号只用于标记层级（几段编号=第几级），
  实际数字由 Word 自动生成并与上文章条连续**——增删条款后整体自动续编，无需手改。

**术语条目**：在 `# 术语和定义` 下写 `## 地热温泉  geothermal hot spring`（中英文之间留两个空格），
渲染为：自动编号 3.1 单独成行，下一行黑体中文术语 + 英文对应词，再下面接定义段。

固定章节顺序建议：`范围` → `规范性引用文件` → `术语和定义` →（`符号和缩略语`）→ 各技术章 → 附录 → `参考文献`。

### 3. 术语和定义

在 `# 术语和定义` 下，每条术语用二级标题，中英文之间用两个空格分隔：

```
## 智能座舱  intelligent cockpit

定义内容写成普通段落。
```

会自动编号为 3.1、3.2……

### 4. 表格

GFM 表格上方写一行表题 `{表：#tbl:id} 标题`（**只写标题，不写“表N”**，编号由 SEQ 域自动生成）：

```
{表：#tbl:classify} 温泉利用分类

| 利用类别 | 适宜水温 |
| --- | --- |
| 医疗保健洗浴 | 36～45 |
```

- 正文表自动编”表1、表2…”；**附录里的表自动编”表A.1、表B.1…”**（按所在附录）。
- `{表：#tbl:id}` 是标记，渲染时自动去掉，标题保留；编号前缀由 Word SEQ 域生成。

### 5. 图

```
![分级流程图 {#fig:flow}](images/flow.png)
```

自动生成“图N 分级流程图”（附录内为“图A.N”）。图片路径相对运行目录或用绝对路径。
锚点 `{#fig:id}` 可选，用于交叉引用。

### 6. 公式

公式用 LaTeX 写在 `$$ … $$` 块里，可加锚点 `{#eq:id}`（**不用手写序号**，由 SEQ 自动编“（1）”）：

```
按{{eq:depth:label}}计算：

$$H = \frac{T_{r} - T_{0}}{G} + h$${#eq:depth}

式中：

H ——循环深度（m）；
```

转换后为 **Word 原生公式（OMML）**，套用模板“标准文件_正文公式”样式：公式居中、
序号 `（1）` 右对齐（附录内公式自动用“标准文件_附录公式”、编号“（A.1）”）。

> 依赖 `latex2mathml`（pip 安装）和 Office 自带的 `MML2OMML.XSL`（自动探测；可用环境变量
> `MD2STD_MML2OMML_XSL` 指定）。若工具链缺失，公式会回退为 LaTeX 纯文本，不影响其余转换。

### 7. 交叉引用

表、图、公式都用 Word 域（SEQ）自动编号，因此可交叉引用、自动续编：

- 在表题/图题/公式后加类型化锚点，如 `{表：#tbl:monitor} 监测要求`、`{#fig:flow}`、`{#eq:depth}`。
- 在正文任意处用双花括号引用。默认仅输出编号：
  `{{tbl:monitor}}` → “2”；`{{eq:depth}}` → “1”。
- 使用修饰符输出类型名或完整题名：
  `{{tbl:monitor:label}}` → “表2”；`{{tbl:monitor:full}}` → “表2　监测要求”；`{{eq:depth:label}}` → “式（1）”。
- 打开 Word 时会提示”更新域”，选”是”即可让所有编号与引用就位（也可全选后按 F9）。

### 6. 附录

一级标题以 `附录` 开头，后跟性质（`规范性`/`资料性`）与标题；字母 A/B 自动分配：

```
# 附录 规范性 分级判定流程

## 判定步骤
按下列步骤……
```

附录内 `##` 自动编号为 A.1、`###` 为 A.1.1。

### 7. 参考文献

```
# 参考文献

GB/T 1.1—2020　标准化工作导则……
ISO 11783　Tractors……
```

每行（或每个列项）一条，套用参考文献条目样式。

### 8. 索引

索引为可选节。按汉语拼音首字母分组，分组使用二级标题，索引项使用 `术语：位置列表`：

```
# 索引

## B

- 必备要素：3.2.5，6.2.2.1，6.2.2.3
- 标准：3.1.2，4.1，4.2

## C

- 参考文献：表 3，8.2，8.13，10.3.2
```

转换后分组使用“标准文件_索引字母”，条目使用“标准文件_索引项”。术语和位置列表之间由 Word 制表位生成点引导线，不要在 Markdown 中手写点线。

### 9. 规范性引用文件交叉引用

在 `# 规范性引用文件` 下，标准条目（如 `GB 5749  生活饮用水卫生标准`）
自动为标准号加书签。文中用 `{{std:GB 5749}}` 即可引用，渲染为"GB 5749"。

示例：`各阶段工作应符合{{std:GB/T 11615}}的规定。` → `各阶段工作应符合GB/T 11615的规定。`

注意：`{{std:...}}` 内的标准号必须与规范性引用文件里的标准号**完全一致**（含空格和斜杠）。

- 模板：`2 团体标准——模板.docx`（GB/T 1.1—2020 母版，带完整命名样式与样式联动自动编号）。
  构建时复制模板并按节回填，不破坏分节符与页眉页脚。
- 编号机制：模板多级列表的每一级用 `pStyle` 绑定到对应段落样式，套用样式即自动编号。
- 代码结构：`md2std/md_parser.py`（解析）、`docx_builder.py`（构建）、`styles.py`（样式名映射）、
  `boilerplate.py`（标准套话）、`mathconv.py`（LaTeX→公式）、`model.py`（中间模型）、`cli.py`（命令行）。
- 编号与引用：章/条/术语用模板样式联动多级列表自动编号；无标题条接入同一列表续编；
  表/图/公式用 Word **SEQ 域**编号、**REF 域**交叉引用（打开时更新域）。

## 已知限制（后续迭代）

- 术语条目用“术语条一”样式 + 自动编号（黑体术语换行），更细排版可继续打磨。
